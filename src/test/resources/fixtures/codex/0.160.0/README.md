# Codex app-server contract baseline

Captured from official `@openai/codex@0.160.0` on Linux using an isolated empty `CODEX_HOME` and disposable reviewed directory. No existing auth files were read, and no turn/inference or paid request was made. `handshake.json` contains actual initialize, signed-out account/read, config/read, model/list and ephemeral thread/start responses; paths are sanitized to `/reviewed/context` and `/isolated/codex-home`. Thread IDs are opaque disposable fixture IDs.

Schemas are generated with `codex app-server generate-json-schema --experimental --out <temp>`; experimental API is needed for named permissions selection/provenance. Production compatibility is pinned to exact 0.160.0; a CLI upgrade requires recapture and review. Unit tests construct adversarial turn/approval/error events against these authoritative generated schemas; those events are mock scenarios, not captures of live inference.

Source audit: official rust-v0.160.0 commit `a956835d020762cb2b570053af06f643a11c0ecc`, `config/src/permissions_toml.rs`, `core/src/config/permissions.rs`, `core/src/tools/spec_plan.rs`, `app-server-protocol/src/protocol/v2/thread.rs`. Named permissions start with restricted empty filesystem and add exact allowlisted entries; the profile has no inheritance or write entries and disables tool network. Windows restricted-token profile cannot enforce absence of root reads and is unsupported. Linux/macOS are schema/source targets; only Linux has been locally captured, and neither OS has live paid integration validation.

CLI authentication is preserved in production. Restriction overrides are process-scoped `-c` arguments; no user config or security setting is persisted. Existing managed constraints are respected: incompatible effective config/profile rejects the operation, with no broader fallback. MCP servers, hooks, enabled plugins and external instruction files are rejected rather than executed in reviewed context mode.

The captured `thread/start` explicitly sets `environments: []` and returns an empty environment list. This disables environment access for every turn without an override; production never sends turn environment overrides. The exact generated ThreadStartParams schema includes this experimental field. `core/src/tools/spec_plan.rs` only exposes filesystem/execution tools when an environment exists; `apply_patch` additionally refuses to execute without a resolved environment. Generation is therefore prompt-only, with the named restricted filesystem profile retained as defense in depth. The local OS sandbox canary was blocked by cloud-host socket-directory constraints; this is not evidence of runtime kernel enforcement.

Persistent Explore retains an adapter-owned empty directory and CLI thread ID. Each turn starts a fresh app-server process, checks CLI-reported auth/account fingerprint, then resumes the same persisted CLI thread; no auth files are read by the plugin. This avoids relying on a stale long-lived CLI auth cache and gives each turn its own cancellation/deadline. Scope changes (project/model/reviewed context/privacy policy), account changes, default model changes and failed/cancelled turns require explicit New conversation. API-key account/read has no stable account identifier, so persistent Explore is unavailable for that auth mode; one-shot generation/Verify remain supported with API billing acknowledgement.

`persistent-empty-resume-error.json` is an actual no-inference process-restart capture: an empty persistent thread has no saved rollout until a turn occurs; resume returns -32600 `no rollout found`. This verifies error handling/protocol shape, not successful live conversation persistence. Valid resume unit scenarios use the generated official schemas and captured thread response shape, clearly synthetic. No production/authenticated/paid inference was invoked. CLI owns persisted conversation history; New clears plugin references and empty directories, but does not delete CLI-managed history files.

Help capture trailing whitespace is normalized for repository formatting; generated JSON schemas retain their original generated structure. The manifest covers every fixture file except itself.
