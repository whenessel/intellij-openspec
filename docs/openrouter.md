# OpenRouter

> **Maintenance: Living** — updated with provider behavior and acceptance evidence.

The setup wizard also offers OpenRouter with an editable model ID; catalog refresh is available in Settings.

Select **Settings → Tools → OpenSpec → REST API → REST provider: OpenRouter**. Enter your OpenRouter API key and click Apply. The key is stored in IntelliJ PasswordSafe, separately from OpenAI and other providers; it is never saved in project settings. OpenRouter uses its own account and credits, independently of Codex login or a ChatGPT subscription.

Click **Refresh models (no inference)** to load the public text-model catalog. Refresh uses no API key and sends no project content. The model field remains editable: paste a provider-qualified ID such as `vendor/model`, or a free variant ending in `:free`. Refresh preserves your selected or typed ID. Hover the selected model or a catalog row to see exact decimal-string USD prices with their units, catalog source and refresh timestamp. Missing prices remain unknown. The default `openrouter/free` routes to an available free model; availability and free-tier rate limits vary. Confirm current prices on OpenRouter before selecting another model. **Test (API billed)** sends a short live request using the selected model and key; testing an unsaved key does not save it.

Generation, Continue, Fast-Forward, Explore and Verify use the same reviewed-context boundary and artifact preview/application as other REST providers. Clipboard and Editor delivery retain their precedence. Explore is a one-shot REST operation with the plugin-supplied context; it does not acquire Codex-owned persistent conversation history. Autonomous workspace Apply and native tool execution are not part of this provider.

Context review identifies OpenRouter and the possible downstream model provider as recipients, and displays the captured routing/privacy policy. Configure **Allowed provider IDs** and **Preferred provider order** as comma-separated IDs. Blank fields allow any eligible provider and OpenRouter's default order. **Allow provider fallback** controls downstream fallback; it does not switch the plugin to Codex or another REST provider. **Provider data collection** defaults to `allow`; select `deny` to restrict collection. **Require zero data retention (ZDR)** defaults off and can restrict eligible routes further. These requirements are sent without being relaxed during retries; an unavailable eligible route fails visibly. Provider policy does not establish a universal retention guarantee.

Requests use a fixed HTTPS endpoint with redirects disabled; the key is sent only in the Authorization header. **Check key status (no inference)** queries the selected key's tier and remaining USD spending limit without sending project content or generating text. Unknown or absent values remain unknown. An unsaved key used for status/test is not persisted; Apply stores it in PasswordSafe. Settings and wizard connection tests use the same SSE transport and captured routing/privacy constraints, with at most 256 output tokens. They do not establish IDE workflow acceptance.

Workflow requests use **SSE streaming**. Explore can display incremental text, while artifacts are applied only after a completed, validated response and accepted preview. The stream must provide a successful stop and terminal marker; truncation, blocked/refused responses, embedded HTTP-200 errors, malformed frames or disconnects fail without applying partial output. Completed workflow requests report the returned actual model and downstream provider in the existing Console; missing provider metadata is reported as unknown.

**Maximum output tokens** defaults to 4096 and accepts 1–16000. Known catalog context/output bounds can lower that allowance; input uses a conservative UTF-8-byte bound with a framing reserve of up to 1024 tokens rather than an exact model tokenizer. Unknown model bounds permit only bounded context (up to 48 KiB); refresh the catalog or reduce context if admission fails. Catalog metadata is refreshed when the cached catalog is older than five minutes; discovery failure preserves manual IDs with conservative bounds. Requests use `max_tokens` and `require_parameters=true`; explicitly required native structured output needs catalog-confirmed `response_format` and `structured_outputs` support and a schema. Normal artifact responses still undergo the shared local envelope/path/base validation.

The workflow deadline is at most five minutes. Cancel interrupts pending transport/read/retry waiting and prevents artifact application; it cannot guarantee a refund for usage already processed. Automatic retry is limited to explicit pre-stream HTTP 429 or 503 responses carrying a valid `Retry-After` of at most ten seconds, with at most three attempts inside the original deadline. No automatic retry occurs after HTTP 200, an ambiguous network failure, or partial stream output. Other errors require an explicit new request.

Errors identify the status and next action without displaying raw provider bodies: 401 key, 402 credits/spending limit, 403 permissions/privacy restrictions, 404 model availability, 429 rate limits and 5xx provider availability. Catalog failures leave manual model entry available.
